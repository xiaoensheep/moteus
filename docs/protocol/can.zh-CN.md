# CAN 协议

寄存器（register）命令集面向实时应用场景。它提供了多级简洁性（conciseness），并且可以在所提供的 FD-CAN 通信总线上以超过 1kHz 的速率运行。

通用定义：

- *字节序（endian-ness）*：所有基本类型均采用最低有效字节（least significant byte）在前的顺序。
- *varuint*：一个或多个 uint8 值组成的序列，按最低有效字节在前排列。对于每个值，其低 7 位（7 LSBs）为数据；若最高位（MSB）被置位，则表示还有更多字节。它最多只能表示一个 uint32，因此 5 字节是最大有效长度。
- *float*：一个 IEEE 754 32 位浮点数。

## CAN 格式

与 moteus 的通信通过 CAN-FD 帧进行，标准位速率为 1Mbit，数据位速率为 5Mbit。

### CAN ID

ID 被构造为一个 16 位数字，高 8 位为“源（source）”，低 8 位为“目的（destination）”。目的地址是 7 位伺服 ID，最高位为 0。源地址是任意的 7 位数字，当 moteus 需要回复该消息时，其最高位为 1。

如果 ID 大于 0x7fff，则该 CAN 帧必须是扩展帧，否则该帧是否为扩展帧则不予考虑。

示例：

ID: 0x8001
 * 从源 0 发送
 * 发往目的 1
 * 第 16 位被置位，因此请求回复

ID: 0x100
 * 从源 1 发送
 * 发往目的 0
 * 不请求回复

### 子帧（Subframes）

每个 CAN-FD 帧包含一个或多个“子帧（subframes）”。下面简要描述了允许使用的子帧类型。权威参考位于
[multiplex/format.h](https://github.com/mjbots/mjlib/blob/master/mjlib/multiplex/format.h)

CAN-FD 帧中所需的任何额外尾部填充字节都应设置为 NOP（0x50）。

#### 写寄存器

*0x00, 0x04, 0x08, 0x0c* - 写（int8|int16|int32|float）

- `varuint` => 寄存器数量（可选择性地编码为子帧类型的非零低 2 位）
- `varuint` => 起始寄存器号
- N x (int8|int16|int32|float) => 值

#### 读寄存器

*0x10, 0x14, 0x18, 0x1c* - 读（int8|int16|int32|float）

- `varuint` => 寄存器数量（可选择性地编码为非零低 2 位）
- `varuint` => 起始寄存器号

#### 回复

*0x20, 0x24, 0x28, 0x2c* - 回复（int8|int16|int32|float）

- `varuint` => 寄存器数量（可选择性地编码为非零低 2 位）
- `varuint` => 起始寄存器号
- N x (int8|int16|int32|float) => 值

#### 错误

*0x30, 0x31* - 写/读错误

- `varuint` => 寄存器号
- `varuint` => 错误号

#### NOP

*0x50* - 无操作


## 示例

一个单独的 CAN-FD 帧即可用于命令伺服器，并同时发起对某些寄存器的查询。一个示例帧可能如下所示，以十六进制编码并附有注释。

- `01` - 写单个 int8 寄存器（寄存器数量编码在低 2 位中）
 - `00` - 起始寄存器号“Mode”
 - `0a` - “position”模式
- `07` - 写 3 个 int16 寄存器（寄存器数量编码在低 2 位中）
 - `20` - 寄存器 0x020
 - `6000` - 位置 = 0x0060 = 96 = 3.456 度
 - `2001` - 速度 = 0x0120 = 288 = 25.92 dps
 - `50ff` - 前馈转矩 = 0xff50 = -176 = 1.76 N*m
- `14` - 读 int16 寄存器
 - `04` - 读 4 个寄存器
 - `00` - 起始于 0x000（因此为 0x000 Mode、0x001 Position、0x002
   Velocity、0x003 Torque）
- `13` - 读 3 个 int8 寄存器
 - `0d` - 起始于 0x00d（因此为 0x00d Voltage、0x00e Temperature、
    0x00f Fault code）

因此，整个 CAN-FD 消息为（十六进制）：

`01000a07206000200150ff140400130d`

要使用 fdcanusb 转换器将上述消息发送到配置为默认地址 1 的设备，可以这样写：

`can send 8001 01000a07206000200150ff140400130d`

ID 中的 `80` 有两个用途。最高位被置位会强制设备做出响应（否则即使发送查询命令也不会响应）。其余位是要回复到的“ID”。针对此命令，伺服器可能的响应如下所示：

`rcv 100 2404000a005000000170ff230d181400`

解码后，其含义为：

- 从设备“1”发往设备“0”的 `100`

- 带有 int16 值的 `24` 回复
 - `04` 4 个寄存器
 - `00` 起始于寄存器 0
 - `0a00` 处于模式 10 - Position
 - `5000` 位置为 0x0050 = 80 = 2.88 度
 - `0001` 速度为 0x0100 = 256 = 23.04 dps
 - `70ff` 转矩为 0xff70 = -144 = -1.44 Nm
- 带有 3 个 int8 值的 `23` 回复
 - `0d` 起始于寄存器 0x00d
 - `18` 电压为 12V
 - `14` 温度为 20C
 - `00` 无故障
